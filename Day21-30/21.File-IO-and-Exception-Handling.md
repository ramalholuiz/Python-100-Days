## File I/O and Exception Handling

In real-world development, you will often encounter scenarios that require data persistence. Persistence refers to transferring data from a storage medium that cannot retain data for a long time (usually memory) to one that can (usually a hard disk). The most direct and simple way to achieve data persistence is through the **file system**, saving data to **files**.

A computer's **file system** is a method of storing and organizing computer data that makes accessing and finding data easy. The file system uses the abstract logical concepts of **files** and **tree-structured directories** to replace the data block concepts of physical devices such as hard drives, optical discs, and flash memory. When users save data using the file system, they don't need to worry about which data block on the hard drive the data is actually stored in — they only need to remember the file path and file name. Before writing new data, users don't need to worry about which data blocks on the hard drive are unused. The storage space management (allocation and deallocation) on the hard drive is handled automatically by the file system — users only need to remember which file the data was written to.

### Opening and Closing Files

With the file system, we can conveniently read and write data through files. In Python, file operations are very simple to implement. We can use Python's built-in `open` function to open files. When using the `open` function, we can specify the **file name**, **operation mode**, and **character encoding** through the function's parameters, and then proceed with file read/write operations. The operation mode mentioned here refers to what type of file to open (character file or binary file) and what operation to perform (read, write, or append), as shown in the table below.

| Mode  | Description                                          |
| ----- | ---------------------------------------------------- |
| `'r'` | Read (default)                                       |
| `'w'` | Write (truncates existing content first)             |
| `'x'` | Write, raises an exception if the file already exists |
| `'a'` | Append, writes content to the end of an existing file |
| `'b'` | Binary mode                                          |
| `'t'` | Text mode (default)                                  |
| `'+'` | Update (both read and write)                         |

When using the `open` function, if the file being opened is a character file (text file), you can specify the character encoding used for reading and writing through the `encoding` parameter. If you're unfamiliar with character encoding and character set concepts, you can read the article [Character Sets and Character Encoding](https://www.cnblogs.com/skynet/archive/2011/05/03/2035105.html); we won't elaborate further here.

After successfully opening a file with the `open` function, it returns a file object through which we can perform read and write operations. If opening the file fails, the `open` function will raise an exception, which we will explain later. To close an opened file, you can use the file object's `close` method, which releases the file when file operations are complete.

### Reading and Writing Text Files

When opening a text file with the `open` function, you need to specify the file name and set the file operation mode to `'r'`. If not specified, the default is also `'r'`. If you need to specify character encoding, you can pass the `encoding` parameter. If not specified, the default is `None`, which means the operating system's default encoding will be used when reading the file. It's important to note that if you can't guarantee that the encoding used when saving the file matches the encoding specified by the `encoding` parameter, then reading the file may fail due to character decoding errors.

The following example demonstrates how to read a plain text file (generally referring to a file composed only of native character encoding — compared to rich text, plain text does not contain style control elements and can be read directly by the simplest text editor).

```python
file = open('致橡树.txt', 'r', encoding='utf-8')
print(file.read())
file.close()
```

> **Note**: "To the Oak Tree" is a love poem created by Shu Ting in March 1977 and is one of my favorite modern poems.

In addition to using the file object's `read` method to read a file, you can also use a `for-in` loop to read line by line, or use the `readlines` method to read the file into a list by lines, as shown in the code below.

```python
file = open('致橡树.txt', 'r', encoding='utf-8')
for line in file:
    print(line, end='')
file.close()

file = open('致橡树.txt', 'r', encoding='utf-8')
lines = file.readlines()
for line in lines:
    print(line, end='')
file.close()
```

If you want to write content to a file, you can use `w` or `a` as the operation mode when opening the file. The former truncates the previous text content and writes new content, while the latter appends new content to the end of the existing content.

```python
file = open('致橡树.txt', 'a', encoding='utf-8')
file.write('\nTitle: "To the Oak Tree"')
file.write('\nAuthor: Shu Ting')
file.write('\nDate: March 1977')
file.close()
```

### Exception Handling Mechanism

Please note the code above — if the file specified by the `open` function doesn't exist or can't be opened, it will raise an exception that causes the program to crash. To make the code robust and fault-tolerant, we can **use Python's exception mechanism to properly handle code that may encounter issues at runtime**. There are five keywords related to exceptions in Python: `try`, `except`, `else`, `finally`, and `raise`. Let's look at the code below first, and then we'll explain the usage of these keywords.

```python
file = None
try:
    file = open('致橡树.txt', 'r', encoding='utf-8')
    print(file.read())
except FileNotFoundError:
    print('Unable to open the specified file!')
except LookupError:
    print('Unknown encoding specified!')
except UnicodeDecodeError:
    print('Decoding error while reading the file!')
finally:
    if file:
        file.close()
```

In Python, we can place code that may encounter issues at runtime inside a `try` block. After `try`, we can add one or more `except` blocks to catch exceptions and handle them accordingly. For example, in the code above, a `FileNotFoundError` is raised if the file is not found, a `LookupError` is raised if an unknown encoding is specified, and a `UnicodeDecodeError` is raised if the file cannot be decoded using the specified encoding. So we follow `try` with three `except` blocks to handle these three different exception situations. After the `except` blocks, we can also add an `else` block — this is code that will execute when no exception occurs in the `try` block, and the code in `else` won't have exception catching, meaning that if an exception occurs, the program will terminate and report the exception. Finally, we use a `finally` block to close the opened file and release external resources acquired by the program. Since the code in the `finally` block executes regardless of whether the program runs normally or encounters an exception — even if the `sys` module's `exit` function is called to terminate the Python program, the code in `finally` will still execute (because the essence of the `exit` function is to raise a `SystemExit` exception) — we call the `finally` block the "always-execute block," making it ideal for releasing external resources.

From the inheritance structure above, we can see that all exceptions in Python are subtypes of `BaseException`, which has four direct subclasses: `SystemExit`, `KeyboardInterrupt`, `GeneratorExit`, and `Exception`. Among them, `SystemExit` indicates the interpreter has requested to exit, `KeyboardInterrupt` means the user interrupted program execution (by pressing `Ctrl+C`), and `GeneratorExit` indicates a generator encountered an exception and notified exit. It's okay if you don't understand these exceptions — just keep learning. Worth mentioning is the `Exception` class, which is the parent type of regular exception types. Many exceptions directly or indirectly inherit from `Exception`. If Python's built-in exception types don't meet your application's needs, you can define custom exception types, which should also directly or indirectly inherit from `Exception`, and you can override or add methods as needed.

In Python, you can use the `raise` keyword to raise an exception (throw an exception object), and the caller can catch and handle the exception using the `try...except...` structure. For example, in a function, when the execution conditions are not met, you can throw an exception to inform the caller of the problem, and the caller can recover from the exception by catching and handling it. The code for defining and raising exceptions is shown below.

```python
class InputError(ValueError):
    """Custom exception type"""
    pass


def fac(num):
    """Calculate factorial"""
    if num < 0:
        raise InputError('Can only calculate factorial of non-negative integers')
    if num in (0, 1):
        return 1
    return num * fac(num - 1)
```

Calling the factorial function `fac`, catching the input error exception through the `try...except...` structure and printing the exception object (displaying exception information). If the input is correct, it calculates the factorial and ends the program.

```python
flag = True
while flag:
    num = int(input('n = '))
    try:
        print(f'{num}! = {fac(num)}')
        flag = False
    except InputError as err:
        print(err)
```

### Context Manager Syntax

For file objects returned by the `open` function, you can also use the `with` context manager syntax to automatically execute the file object's `close` method after file operations are complete. This makes the code simpler and more elegant, as you no longer need to write a `finally` block to close the file and release resources. It's important to note that not all objects can be used with the `with` context syntax — only objects that conform to the **context manager protocol** (having `__enter__` and `__exit__` magic methods) can use this syntax. Python's standard library `contextlib` module also provides support for the `with` context syntax, which we'll explain when needed later.

The code rewritten with `with` context syntax is shown below.

```python
try:
    with open('致橡树.txt', 'r', encoding='utf-8') as file:
        print(file.read())
except FileNotFoundError:
    print('Unable to open the specified file!')
except LookupError:
    print('Unknown encoding specified!')
except UnicodeDecodeError:
    print('Decoding error while reading the file!')
```

### Reading and Writing Binary Files

Reading and writing binary files is similar to reading and writing text files, but note that when using the `open` function, if performing a read operation, the mode is `'rb'`, and for a write operation, the mode is `'wb'`. Another point: when reading and writing text files, the return value of the `read` method and the parameter of the `write` method are `str` objects (strings), while for binary files, the return value of `read` and the parameter of `write` are `bytes-like` objects (byte strings). The code below copies an image file named `guido.jpg` in the current path to a file called `吉多.jpg`.

```python
try:
    with open('guido.jpg', 'rb') as file1:
        data = file1.read()
    with open('吉多.jpg', 'wb') as file2:
        file2.write(data)
except FileNotFoundError:
    print('The specified file cannot be opened.')
except IOError:
    print('Error occurred while reading/writing the file.')
print('Program execution complete.')
```

If the image file to be copied is very large, reading the entire file content into memory at once may cause significant memory overhead. To reduce memory usage, you can pass a `size` parameter to the `read` method to specify the number of bytes to read each time, and complete the operation through a loop of reading and writing, as shown in the code below.

```python
try:
    with open('guido.jpg', 'rb') as file1, open('吉多.jpg', 'wb') as file2:
        data = file1.read(512)
        while data:
            file2.write(data)
            data = file1.read()
except FileNotFoundError:
    print('The specified file cannot be opened.')
except IOError:
    print('Error occurred while reading/writing the file.')
print('Program execution complete.')
```

### Summary

Through file read/write operations, we can achieve data persistence. In Python, you can obtain file objects through the `open` function and implement file read/write operations through the file object's `read` and `write` methods. Programs may encounter unforeseen exceptional situations at runtime, and Python's exception mechanism can be used to handle these situations. Python's exception mechanism mainly includes five core keywords: `try`, `except`, `else`, `finally`, and `raise`. The `except` statement after `try` is not mandatory, and the `finally` statement is also not mandatory, but at least one of them must be present. There can be one or more `except` statements, and multiple `except` blocks will be matched in the order they are written — if an exception has already been handled, subsequent `except` statements won't be entered. The `except` statement can also specify multiple exception types simultaneously using a tuple for catching. If no exception type is specified after `except`, it defaults to catching all exceptions. After catching an exception, you can use `raise` to re-throw it, but it's not recommended to catch and re-throw the same exception. It's not recommended to catch all exceptions without understanding the logic, as this may mask serious problems in the program. Finally, one important point: **don't use the exception mechanism to handle normal business logic or control program flow** — simply put, don't abuse the exception mechanism. This is a common mistake made by beginners.
