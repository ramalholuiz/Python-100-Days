# SQL DCL Explained

Database servers typically contain important data. Access control ensures data security, and DCL solves this problem by granting access permissions to specified users or revoking permissions. DCL is critical for database administrators since user permission management relates directly to database security. Simply put, DCL allows trusted users database access, blocks untrusted users, and minimizes each user's permissions (principle of least privilege—only necessary permissions).

## Creating Users

Create a user and specify access credentials using the following SQL:

```sql
CREATE USER 'john_doe'@'%' IDENTIFIED BY 'Pass.123';
```

This SQL creates user `john_doe` with password `Pass.123`, accessible from any host (using wildcard `%` after @). To restrict `john_doe` to access only from the `192.168.0.x` network segment:

```sql
DROP USER IF EXISTS 'john_doe'@'%';

CREATE USER 'john_doe'@'192.168.0.%' IDENTIFIED BY 'Pass.123';
```

After creation, the `john_doe` account has almost no permissions to perform operations.

## Granting Permissions

Grant `john_doe` permission to query the school database's college table (`tb_college`):

```sql
GRANT SELECT ON `school`.`tb_college` TO 'john_doe'@'192.168.0.%';
```

Allow `john_doe` query permissions on all school database objects:

```sql
GRANT SELECT ON `school`.* TO 'john_doe'@'192.168.0.%';
```

If `john_doe` also needs insert, delete, and update permissions:

```sql
GRANT INSERT, DELETE, UPDATE ON `school`.* TO 'john_doe'@'192.168.0.%';
```

To grant DDL execution permissions:

```sql
GRANT CREATE, DROP, ALTER ON `school`.* TO 'john_doe'@'192.168.0.%';
```

To grant all permissions on all databases and objects (generally not recommended since regular accounts shouldn't have such extensive permissions):

```sql
GRANT ALL PRIVILEGES ON *.* TO 'john_doe'@'192.168.0.%';
```

## Revoking Permissions

Revoke `john_doe`'s insert, delete, and update permissions on the school database:

```sql
REVOKE INSERT, DELETE, UPDATE ON `school`.* FROM 'john_doe'@'192.168.0.%';
```

Revoke all permissions:

```sql
REVOKE ALL PRIVILEGES ON *.* FROM 'john_doe'@'192.168.0.%';
```

Note that since databases may cache user permissions, execute the following statement after granting or revoking permissions to make new permissions take immediate effect:

```sql
FLUSH PRIVILEGES;
```
