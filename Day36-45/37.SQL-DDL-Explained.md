# SQL DDL Explained

SQL can be divided into four categories: DDL (Data Definition Language), DML (Data Manipulation Language), DCL (Data Control Language), and TCL (Transaction Control Language). DDL is mainly used to create, delete, and modify database objects, such as creating, deleting, and modifying tables. Core keywords include `create`, `drop`, and `alter`. DML is responsible for inserting, deleting, updating, and querying data, with keywords including `insert`, `delete`, `update`, and `select`. DCL is used to grant and revoke permissions, with core keywords being `grant` and `revoke`. TCL is typically used for transaction control.

> **Note**: SQL is case-insensitive. It's generally recommended to write keywords in uppercase and other parts in lowercase. If your company has SQL coding standards, follow those standards—professional coding standards should take precedence over personal preferences.

## Creating Databases and Tables

Let's implement a simple school course selection system database. We'll name the database `school`, and the four key entities are colleges, teachers, students, and courses. Students belong to colleges (many-to-one relationship: multiple students per college, one college per student). Similarly, teachers belong to colleges (many-to-one relationship). One teacher can teach multiple courses; if only one teacher teaches a course, it's a many-to-one relationship; if multiple teachers teach together, it's a many-to-many relationship. For simplicity, we'll design courses and teachers as many-to-one. Students and courses form a typical many-to-many relationship (one student can take multiple courses, one course can be taken by multiple students). Relational databases need intermediate tables to maintain many-to-many relationships. Our school course selection system has five tables: colleges (`tb_college`), students (`tb_student`), teachers (`tb_teacher`), courses (`tb_course`), and course selection records (`tb_record`), where the course selection records table serves as the intermediate table for the student-course many-to-many relationship.

```sql
-- Drop the school database if it exists
DROP DATABASE IF EXISTS `school`;

-- Create the school database with default character set and collation
CREATE DATABASE `school` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- Switch to the school database context
USE `school`;

-- Create college table
CREATE TABLE `tb_college`
(
`col_id`    int unsigned AUTO_INCREMENT      COMMENT 'College ID',
`col_name`  varchar(50)  NOT NULL            COMMENT 'College name',
`col_intro` varchar(500) NOT NULL DEFAULT '' COMMENT 'College introduction',
PRIMARY KEY (`col_id`)
);

-- Create student table
CREATE TABLE `tb_student`
(
`stu_id`    int unsigned NOT NULL           COMMENT 'Student ID',
`stu_name`  varchar(20)  NOT NULL           COMMENT 'Student name',
`stu_sex`   boolean      NOT NULL DEFAULT 1 COMMENT 'Gender',
`stu_birth` date         NOT NULL           COMMENT 'Date of birth',
`stu_addr`  varchar(255) DEFAULT ''         COMMENT 'Address',
`col_id`    int unsigned NOT NULL           COMMENT 'College ID',
PRIMARY KEY (`stu_id`),
CONSTRAINT `fk_student_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Create teacher table
CREATE TABLE `tb_teacher`
(
`tea_id`    int unsigned NOT NULL                COMMENT 'Teacher ID',
`tea_name`  varchar(20)  NOT NULL                COMMENT 'Teacher name',
`tea_title` varchar(10)  NOT NULL DEFAULT 'Assistant Professor' COMMENT 'Title',
`col_id`    int unsigned NOT NULL                COMMENT 'College ID',
PRIMARY KEY (`tea_id`),
CONSTRAINT `fk_teacher_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Create course table
CREATE TABLE `tb_course`
(
`cou_id`     int unsigned NOT NULL COMMENT 'Course ID',
`cou_name`   varchar(50)  NOT NULL COMMENT 'Course name',
`cou_credit` int          NOT NULL COMMENT 'Credits',
`tea_id`     int unsigned NOT NULL COMMENT 'Teacher ID',
PRIMARY KEY (`cou_id`),
CONSTRAINT `fk_course_tea_id` FOREIGN KEY (`tea_id`) REFERENCES `tb_teacher` (`tea_id`)
);

-- Create course selection record table
CREATE TABLE `tb_record`
(
`rec_id`   bigint unsigned AUTO_INCREMENT COMMENT 'Record ID',
`stu_id`   int unsigned    NOT NULL       COMMENT 'Student ID',
`cou_id`   int unsigned    NOT NULL       COMMENT 'Course ID',
`sel_date` date            NOT NULL       COMMENT 'Selection date',
`score`    decimal(4,1)                   COMMENT 'Exam score',
PRIMARY KEY (`rec_id`),
CONSTRAINT `fk_record_stu_id` FOREIGN KEY (`stu_id`) REFERENCES `tb_student` (`stu_id`),
CONSTRAINT `fk_record_cou_id` FOREIGN KEY (`cou_id`) REFERENCES `tb_course` (`cou_id`),
CONSTRAINT `uk_record_stu_cou` UNIQUE (`stu_id`, `cou_id`)
);
```

There are several important points to highlight about the above DDL:

- First, all database names, table names, and column names are enclosed in backticks (`). Backticks are not required but help avoid conflicts when names match SQL keywords (words with special meaning in SQL).

- When creating a database, we specify the default character set as `utf8mb4` (4-byte UTF-8 encoding) using `default character set utf8mb4`. We recommend using this character set, which is also the default in MySQL 8.x, as it supports internationalization and can store Emoji characters. You can view MySQL's supported character sets and default collations using:

  ```sql
  show character set;
  ```

  ```ini
  [mysqld]
  character-set-server=utf8
  ```

  > **Tip**: If you're unsure how to modify the MySQL configuration file, skip this for now.

- When creating and dropping databases, the keyword `database` can be replaced with `schema`—they have the same effect.

- In the table creation statement, `NOT NULL` is a NOT NULL constraint, restricting the field from being empty. `DEFAULT` specifies a default value for the field (default value constraint). `PRIMARY KEY` is a primary key constraint, setting the column(s) that uniquely identify a record. A primary key cannot have duplicate values. `FOREIGN KEY` is a foreign key constraint maintaining referential integrity between tables. For example, since the student table has a foreign key constraint on the `col_id` field, it must reference (`references`) a college ID from the college table; you cannot assign arbitrary values. To name primary key constraints, foreign key constraints, etc., use the `constraint` keyword followed by the constraint name.

- The `comment` keyword adds annotations to columns and tables, improving code readability and maintainability.

- When creating a table, you can choose the underlying storage engine. MySQL supports multiple storage engines, viewable with `show engines`. Since MySQL 5.5, the default engine is InnoDB, which we recommend (better suited for internet applications needing high concurrency, performance, and transaction support). For SQL backward compatibility, you can specify InnoDB explicitly after the closing parenthesis with `engine=innodb`.

  ```sql
  show engines\G
  ```

  > **Note**: The \G above changes the output format. When using the command-line client, if a table has many fields, output on one line becomes difficult to read. Using \G displays each record's columns on separate lines, which is much more comfortable in the command-line client.

  When choosing data types, VARCHAR and CHAR are commonly used for character strings. VARCHAR is variable-length, while CHAR is fixed-length. For InnoDB storage engine, row storage format doesn't distinguish between fixed and variable columns, so VARCHAR and CHAR don't have essential performance differences. For very large strings, use TEXT type; for large byte strings, use BLOB (Binary Large Object) type. MySQL includes TEXT, MEDIUMTEXT, LONGTEXT and BLOB, MEDIUMBLOB, LONGBLOB variants, differing mainly in maximum storage size. Use FLOAT or DOUBLE for floating-point numbers (FLOAT is no longer recommended and may be removed in future versions). Use DECIMAL for fixed-point numbers, allowing you to specify significant digits before and after the decimal point. For dates and times, DATETIME is preferred over TIMESTAMP as it represents a wider range; TIMESTAMP is essentially an integer recording milliseconds since 1970-01-01 00:00:00 and will overflow after 2038-01-19 03:14:07.

  For auto-increment fields (`AUTO_INCREMENT`), MySQL 5.x has issues with auto-increment value rollback, but this is well-solved in MySQL 8.x. Additionally, MySQL 8.x has many other improvements in both functionality and performance, making it strongly recommended. For high-concurrency database access, AUTO_INCREMENT has performance issues and may create duplicate IDs in multi-machine architectures. In such scenarios, distributed ID generation algorithms (SnowFlake, TinyID, etc.) are better choices. Interested readers can research these algorithms.

## Dropping Tables and Modifying Tables

Using the student table as an example, we'll demonstrate dropping and modifying tables. Drop tables using `drop table`:

```sql
DROP TABLE `tb_student`;
```

Or:

```sql
DROP TABLE IF EXISTS `tb_student`;
```

Note that if data has been entered into the student table and is referenced by other tables, the drop operation will fail. In the next lesson, we'll demonstrate inserting data; try dropping the student table then to see what happens.

To modify the student table, use `alter table`, with several scenarios:

Add a new column to the table, for example, adding a phone number field to the student table:

```sql
ALTER TABLE `tb_student` ADD COLUMN `stu_tel` varchar(20) NOT NULL COMMENT 'Phone number';
```

> **Note**: If you specify a NOT NULL constraint when adding a column, the table cannot have existing data. Otherwise, original rows would have no value for the new column, violating the NOT NULL constraint. You can solve this by using a DEFAULT constraint when adding the column.

Delete a specified column, for example, removing the phone number column just added:

```sql
ALTER TABLE `tb_student` DROP COLUMN `stu_tel`;
```

Modify a column's data type, for example, changing `stu_sex` to a character:

```sql
ALTER TABLE `tb_student` MODIFY COLUMN `stu_sex` char(1) NOT NULL DEFAULT 'M' COMMENT 'Gender';
```

Rename a column, for example, changing `stu_sex` to `stu_gender`:

```sql
ALTER TABLE `tb_student` CHANGE COLUMN `stu_sex` `stu_gender` boolean DEFAULT 1 COMMENT 'Gender';
```

Drop constraint conditions, for example, removing the foreign key constraint on the `col_id` column:

```sql
ALTER TABLE `tb_student` DROP FOREIGN KEY `fk_student_col_id`;
```

Add constraint conditions, for example, adding a foreign key constraint to the `col_id` column:

```sql
ALTER TABLE `tb_student` ADD FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`);
```

Or:

```sql
ALTER TABLE `tb_student` ADD CONSTRAINT `fk_student_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`);
```

> **Note**: When adding foreign key constraints, you can use `ON UPDATE` and `ON DELETE` to specify actions when the referenced table undergoes delete and update operations. Default values are `restrict`, meaning updates and deletes are not allowed if foreign key constraints exist. Besides `restrict`, possible values include `cascade` (cascading operations) and `set null` (set to null). Interested readers can research these options.

Rename the table, for example, changing the student table name to `tb_stu_info`:

```sql
ALTER TABLE `tb_student` RENAME TO `tb_stu_info`;
```

> **Tip**: Generally, avoid lightly modifying database or table names.
