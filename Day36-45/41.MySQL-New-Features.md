# MySQL New Features

## JSON Data Type

Many developers feel that structured storage in relational databases lacks flexibility since you must predefine all columns and their data types. When business evolves and changes, modifying table structures becomes tedious. Starting with MySQL 5.7, MySQL introduced JSON data type support (MySQL 8.0 resolved JSON's logging performance bottleneck), and leveraging JSON types effectively breaks boundaries between relational and NoSQL databases, providing greater convenience for data persistence operations.

JSON types primarily consist of JSON objects and JSON arrays:

1. **JSON Object**

```json
{"name": "John Doe", "tel": "13122335566", "qq": "957658"}
```

2. **JSON Array**

```json
[1, 2, 3]
```

```json
[{"name": "John Doe", "tel": "13122335566"}, {"name": "Jane Smith", "qq": "123456"}]
```

When would you use JSON types? Consider a simple example: many products support multiple login methods (phone number, WeChat, QQ, Weibo, etc.), but typically don't require users to provide all login information. Traditional design would require multiple columns for different login methods, possibly with NULL values—not ideal. Moreover, adding a new login method would necessitate table structure modifications. With JSON types, this problem is elegantly solved:

```sql
CREATE TABLE `tb_test`
(
`user_id`    bigint unsigned,
`login_info` json,
PRIMARY KEY (`user_id`)
);

INSERT INTO `tb_test` 
VALUES 
    (1, '{"tel": "13122335566", "qq": "654321", "wechat": "jackfrued"}'),
    (2, '{"tel": "13599876543", "weibo": "wangdachui123"}');
```

To query users' phone numbers and WeChat IDs:

```sql
SELECT `user_id`
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.tel')) AS Phone
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.wechat')) AS WeChat 
FROM `tb_test`;
```

```
+---------+-------------+-----------+
| user_id | Phone       | WeChat    |
+---------+-------------+-----------+
|       1 | 13122335566 | jackfrued |
|       2 | 13599876543 | NULL      |
+---------+-------------+-----------+
```

MySQL provides helper functions like `json_extract` and `json_unquote` for JSON data processing. There's also a more concise syntax:

```sql
SELECT `user_id`
     , `login_info` ->> '$.tel' AS Phone
     , `login_info` ->> '$.wechat' AS WeChat
  FROM `tb_test`;
```

Another example: for user profiling (tagging users), you can store user profile data using JSON types. Create a tags table:

```sql
CREATE TABLE `tb_tags`
(
`tag_id`   int unsigned NOT NULL COMMENT 'Tag ID',
`tag_name` varchar(20)  NOT NULL COMMENT 'Tag Name',
PRIMARY KEY (`tag_id`)
);

INSERT INTO `tb_tags` (`tag_id`, `tag_name`) 
VALUES
    (1, '1970s Generation'),
    (2, '1980s Generation'),
    (3, '1990s Generation'),
    (4, '2000s Generation'),
    (5, 'Sports Enthusiast'),
    (6, 'Highly Educated'),
    (7, 'Refined Taste'),
    (8, 'Home Owner'),
    (9, 'Car Owner'),
    (10, 'Movie Lover'),
    (11, 'Online Shopper'),
    (12, 'Frequent Food Deliverer');
```

Tag users:

```sql
CREATE TABLE `tb_users_tags`
(
`user_id`   bigint unsigned NOT NULL COMMENT 'User ID',
`user_tags` json            NOT NULL COMMENT 'User Tags'
);

INSERT INTO `tb_users_tags`
VALUES
    (1, '[2, 6, 8, 10]'),
    (2, '[3, 10, 12]'),
    (3, '[3, 8, 9, 11]');
```

Query users who are movie lovers (tag 10):

```sql
SELECT `user_id`
  FROM `tb_users_tags`
 WHERE 10 MEMBER OF (`user_tags`->'$');
```

Query 1980s generation (tag 2) movie lovers (tag 10):

```sql
SELECT `user_id`
  FROM `tb_users_tags`
 WHERE JSON_CONTAINS(`user_tags`->'$', '[2, 10]');
```

Query users who are movie lovers OR 1980s generation OR 1990s generation:

```sql
SELECT `user_id`
  FROM `tb_users_tags`
 WHERE JSON_OVERLAPS(user_tags->'$', '[2, 3, 10]');
```

> **Note**: The above queries use the `member of` predicate and two JSON functions. `json_contains` checks if a JSON array contains specified elements, while `json_overlaps` checks if arrays have overlapping elements.

## Window Functions

MySQL 8.0 introduced window function support. Most commercial and some open-source databases provide window functions, also called OLAP (Online Analytical Processing) functions, related to statistics and analysis. To help understand window functions, let's first explain the concept of "windows."

A window is a collection of records. Window functions execute on record sets satisfying certain conditions, executing for each record individually. Window functions differ from aggregate functions: aggregates collapse multiple records into one; window functions execute for each record without changing the total record count. Window functions are more than individual functions—they represent complete syntax. Basic syntax:

```sql
<window_function> OVER (PARTITION BY <grouping_column> ORDER BY <sorting_column> ROWS BETWEEN ... AND ...)
<window_function> OVER (PARTITION BY <grouping_column> ORDER BY <sorting_column> RANGE BETWEEN ... AND ...)
```

Window functions can be:

1. **Specialized window functions**: `lead`, `lag`, `first_value`, `last_value`, `rank`, `dense_rank`, `row_number`, etc.
2. **Aggregate functions**: `sum`, `avg`, `max`, `min`, `count`, etc.

Example 1: Query employees ranked 4th to 6th by salary (highest to lowest):

```sql
SELECT * 
  FROM (SELECT `ename`
             , `sal`
             , ROW_NUMBER() over (ORDER BY `sal` DESC) AS `rk`
	      FROM `tb_emp`) AS `temp`
 WHERE `rk` between 4 and 6;
```

Example 2: Query the two highest-paid employees per department:

```sql
select `ename`, `sal`, `dname` 
from (
    select 
        `ename`, `sal`, `dno`,
        rank() over (partition by `dno` order by `sal` desc) as `rank`
    from `tb_emp`
) as `temp` natural join `tb_dept` where `rank`<=2;
```
