# SQL DML Explained

Continuing from the school course selection database created in the previous lesson, we'll now explain DML usage. DML helps insert data into tables (`insert` operation), delete data from tables (`delete` operation), and update table data (`update` operation). Before executing DML, switch to the `school` database using the `use` command:

```sql
USE `school`;
```

## Insert Operation

As its name suggests, `insert` adds rows to tables. Insertion methods include: inserting complete rows, inserting partial rows, inserting multiple rows, and inserting query results. Here's how to add a college to the colleges table:

```sql
INSERT INTO `tb_college` 
VALUES
    (DEFAULT, 'School of Computer Science', 'A place to study computer science and technology');
```

Since the college table's primary key is auto-increment, use `default` to indicate default value. Alternatively, complete the same operation using:

```sql
INSERT INTO `tb_college` (`col_name`, `col_intro`) 
VALUES 
    ('School of Computer Science', 'A place to study computer science and technology');
```

We recommend this approach: specify which fields to assign values, allowing you not to follow the original field order. The fields listed before `values` determine the assignment order, but except for fields allowing `null` and fields with defaults, all other fields must be listed with values in the `values` tuple. To insert multiple records at once, add multiple tuples after `values`:

```sql
INSERT INTO `tb_college` 
    (`col_name`, `col_intro`) 
VALUES 
    ('School of Foreign Languages', 'School for learning international languages'),
    ('School of Economics and Management', 'Economics for prosperity and management for national governance'),
    ('School of Physical Education', 'Develop athletic sports and enhance people''s health');
```

When inserting data, remember primary keys cannot be duplicate. If inserted data has a primary key matching an existing record, the `insert` operation produces a "Duplicated Entry" error. Again, if `insert` omits some columns, those columns must either have default values or allow `null`, otherwise an error occurs. In business systems, to prevent `insert` operations from impacting other operations' performance (especially `select` operations discussed later), add `low_priority` between `insert` and `into` to lower insertion priority. This approach also applies to the following `delete` and `update` operations.

Assume a table named `tb_temp` has columns `a` and `b` storing college names and introductions respectively. You can also use query results to insert data into the college table:

```sql
INSERT INTO `tb_college`
    (`col_name`, `col_intro`)
SELECT `a`, `b` 
  FROM `tb_temp`;
```

## Delete Operation

Delete data from tables using `delete`, which removes specified rows or all rows. For example, to delete a college with ID `1`:

```sql
DELETE
  FROM `tb_college`
 WHERE col_id=1;
```

Note the `where` clause specifies conditions; only rows satisfying conditions are deleted. Writing the following SQL would delete all college records—very dangerous and seldom done in practice:

```sql
DELETE
  FROM `tb_college`;
```

Even if you delete all data, `delete` doesn't remove the table itself or reset the AUTO_INCREMENT value. To delete all data and reset AUTO_INCREMENT, use `truncate table` for table truncation. `truncate` essentially drops the original table and recreates it, which is faster since data isn't deleted row-by-row. However, remember: deleting data with `truncate table` is extremely dangerous as it removes all data, and since the original table is deleted, recovering mistakenly deleted data becomes very difficult.

## Update Operation

Modify table data using `update`, which can update specified rows or all rows. For example, change student "Yang Guo" to "Yang Xiao", assuming the student ID is `1001`:

```sql
UPDATE `tb_student`
   SET `stu_name`='Yang Xiao'
 WHERE `stu_id`=1001;
```

Note the `where` clause filters by student ID to identify the specific student, then uses assignment to change the name to "Yang Xiao". Why not filter by name? Because multiple students might share the same name. Using `stu_name` as the condition could update multiple records unintentionally. Another important point: in `update` statements, `=` doesn't mean assignment but equality comparison. Only `=` after the `set` keyword performs assignment.

To simultaneously update a student's name and birth date:

```sql
UPDATE `tb_student`
   SET `stu_name`='Yang Xiao'
     , `stu_birth`='1975-12-29'
 WHERE `stu_id`=1001;
```

`update` statements can also use query results to update specified table data. Interested readers can explore this independently. When writing `update` statements, include a `where` clause since whole-table updates are rarely done in practice—this is crucial.
