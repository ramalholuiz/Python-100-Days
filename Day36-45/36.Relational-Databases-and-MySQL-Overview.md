# Relational Databases and MySQL Overview

## Overview of Relational Databases

1. **Data Persistence** - Storing data in storage media that can retain data for long periods, ensuring data is not lost even in case of power failure.

2. **Database Evolution** - The history of database technologies includes network databases, hierarchical databases, relational databases, NoSQL databases, and NewSQL databases.

   > In 1970, IBM researcher E.F. Codd published a paper titled "A Relational Model of Data for Large Shared Data Banks" in *Communication of the ACM*, which introduced the concept of the **relational model** and established its theoretical foundation. Subsequently, Codd published multiple articles discussing normalization theory and 12 criteria for evaluating relational systems, laying a mathematical foundation for relational databases.

3. **Characteristics of Relational Databases**

   - **Theoretical Foundation**: **Relational algebra** (set theory, first-order predicate logic, relational operations)
   - **Visual Representation**: Data organized in **two-dimensional tables** (rows and columns)
   - **Programming Language**: **Structured Query Language (SQL)**
       - DDL: Data Definition Language
       - DML: Data Manipulation Language
       - DCL: Data Control Language
       - TCL: Transaction Control Language

4. **ER Model (Entity-Relationship Model) and Conceptual Data Model Diagrams**

   The **ER Model**, or **Entity-Relationship Model**, was introduced by Chen Pin-Shan, a Chinese-American computer scientist, as a high-level description method for conceptual data models, as shown in the diagram below.

   ![ER Diagram](res/er_diagram.png)

   - **Entity** - Represented by rectangles
   - **Attribute** - Represented by ovals
   - **Relationship** - Represented by diamonds
   - **Cardinality** - 1:1 (one-to-one) / 1:N (one-to-many) / M:N (many-to-many)

   In practical project development, we can use database modeling tools (such as PowerDesigner) to draw conceptual data models, and then convert them into physical models for target database systems. This allows us to generate SQL for creating tables (many tools can export SQL based on our designed physical models and target databases, or directly generate database tables).

   ![Conceptual Model](res/conceptual_model.png)

5. **Relational Database Products**
   - [Oracle](https://www.oracle.com/index.html) - Currently the most widely used database management system in the world. As a general-purpose database system, it has complete data management capabilities; as a relational database, it is a fully relational product; as a distributed database, it implements distributed processing features. Recent versions of Oracle also introduce multi-tenant architecture for easy database cloud deployment and management.
   - [DB2](https://www.ibm.com/analytics/us/en/db2/) - Developed by IBM, primarily running on Unix (including IBM's own AIX), Linux, and Windows Server systems. DB2 has a long history and is considered one of the first databases to use SQL, featuring strong business intelligence capabilities.
   - [SQL Server](https://www.microsoft.com/en-us/sql-server/) - Developed and promoted by Microsoft. Initially designed for small and medium-sized enterprise data management, its application scope has expanded in recent years, with some large enterprises and multinational corporations building their data management systems on it.
   - [MySQL](https://www.mysql.com/) - MySQL is open-source software that anyone can download and modify according to their needs under the GPL (General Public License). MySQL is highly regarded for its speed, reliability, and adaptability.
   - [PostgreSQL](https://www.postgresql.org/) - Open-source relational database product distributed under the BSD license.

## Introduction to MySQL

MySQL was originally developed by the Swedish company MySQL AB as an open-source relational database management system. The company was acquired by Sun Microsystems Inc. in 2008. In 2009, Oracle Corporation acquired Sun Microsystems, making MySQL part of Oracle's product portfolio.

In the past, MySQL became the most popular open-source database due to its high performance, low cost, and reliability, and was widely used in small and medium-sized website development. As MySQL has matured, it has increasingly been adopted in larger-scale websites and applications, including Wikipedia, Google, Facebook, Baidu, Taobao, Tencent, Sina, and Qunar, all using MySQL for data persistence services.

After Oracle's acquisition of Sun Microsystems, it significantly raised the price of MySQL's commercial version and discontinued support for another free software project, OpenSolaris. This raised concerns in the free software community about whether Oracle would continue supporting MySQL's community edition (the only free version among MySQL distributions). Consequently, MySQL founder Michael "Monty" Widenius created [MariaDB](https://mariadb.org/) (named after his daughter) as a MySQL fork. Many companies that originally used MySQL (for example, Wikipedia) have gradually migrated to MariaDB.

### Linux Environment

Below is an example of installing MySQL 5.7.x on CentOS 7.x. For installing other versions on other Linux systems, please refer to the appropriate installation guides online.

1. Install MySQL.

   Download the installation files from the [MySQL official website](https://www.mysql.com/). Select the platform and version on the download page, then download the archive file containing all installation files. After extracting, install using the package management tool.

   ```bash
   wget https://dev.mysql.com/get/Downloads/MySQL-5.7/mysql-5.7.26-1.el7.x86_64.rpm-bundle.tar
   tar -xvf mysql-5.7.26-1.el7.x86_64.rpm-bundle.tar
   ```

   If there are MariaDB files on the system, remove them first.

   ```bash
   yum list installed | grep mariadb | awk '{print $1}' | xargs yum erase -y
   ```

   Update and install required dependencies.

   ```bash
   yum update
   yum install -y libaio libaio-devel
   ```

   Install MySQL using RPM (Redhat Package Manager) in the following order:

   ```bash
   rpm -ivh mysql-community-common-5.7.26-1.el7.x86_64.rpm
   rpm -ivh mysql-community-libs-5.7.26-1.el7.x86_64.rpm
   rpm -ivh mysql-community-libs-compat-5.7.26-1.el7.x86_64.rpm
   rpm -ivh mysql-community-devel-5.7.26-1.el7.x86_64.rpm
   rpm -ivh mysql-community-client-5.7.26-1.el7.x86_64.rpm
   rpm -ivh mysql-community-server-5.7.26-1.el7.x86_64.rpm
   ```

   Check installed MySQL-related packages:

   ```bash
   rpm -qa | grep mysql
   ```

2. Configure MySQL.

   MySQL configuration file is located in `/etc` directory with the name `my.cnf`. The default configuration file content is shown below:

   ```bash
   cat /etc/my.cnf
   ```

   ```ini
   # For advice on how to change settings please see
   # http://dev.mysql.com/doc/refman/5.7/en/server-configuration-defaults.html
   
   [mysqld]
   #
   # Remove leading # and set to the amount of RAM for the most important data
   # cache in MySQL. Start at 70% of total RAM for dedicated server, else 10%.
   # innodb_buffer_pool_size = 128M
   #
   # Remove leading # to turn on a very important data integrity option: logging
   # changes to the binary log between backups.
   # log_bin
   #
   # Remove leading # to set options mainly useful for reporting servers.
   # The server defaults are faster for transactions and fast SELECTs.
   # Adjust sizes as needed, experiment to find the optimal values.
   # join_buffer_size = 128M
   # sort_buffer_size = 2M
   # read_rnd_buffer_size = 2M
   datadir=/var/lib/mysql
   socket=/var/lib/mysql/mysql.sock
   
   # Disabling symbolic-links is recommended to prevent assorted security risks
   symbolic-links=0
   
   log-error=/var/log/mysqld.log
   pid-file=/var/run/mysqld/mysqld.pid
   ```

   Through the configuration file, we can modify MySQL service settings such as port, character set, maximum connections, socket queue size, maximum packet size, log file location, and log retention period. We can also use configuration modifications for performance tuning and security management.

3. Start MySQL service.

   Use the following command to start MySQL:

   ```bash
   service mysqld start
   ```

   On CentOS 7, it's more recommended to use:

   ```bash
   systemctl start mysqld
   ```

   After MySQL starts successfully, check network port usage with:

   ```bash
   netstat -ntlp | grep mysql
   ```

   Or find the MySQL process:

   ```bash
   pgrep mysqld
   ```

4. Connect to the server using MySQL client tools.

   Command-line tool:

   ```bash
   mysql -u root -p
   ```

   > Note: The `-u` parameter specifies the username; MySQL's default super admin account is `root`; `-p` indicates password input (user password); if connecting to another host instead of localhost, use `-h` to specify the host name or IP address.

   For first-time installation, find the default initial password using:

   ```bash
   cat /var/log/mysqld.log | grep password
   ```

   This command displays MySQL log lines containing "password". The part after `root@localhost:` is the default initial password.

   After entering the client tool, change the root password to `123456` using:

   ```sql
   set global validate_password_policy=0;
   set global validate_password_length=6;
   alter user 'root'@'localhost' identified by '123456';
   ```

   > **Note**: Recent MySQL versions don't allow weak passwords by default. The above code modifies the password validation policy and length requirements. We shouldn't use weak passwords in practice due to the risk of brute-force attacks. In recent years, incidents of database attacks, data theft, and ransomware extortion have become increasingly common. To avoid these risks, the most important step is **not to expose the database server on public networks** (ideally place databases on internal networks; at minimum, don't expose database service ports to the internet). Additionally, protect the `root` account password carefully, and **create accounts with appropriate permissions for application access rather than using the root account**.

   When reconnecting with the client tool later, you can use the new password. In practical development, to facilitate user operations, choose graphical client tools to connect to MySQL:

   - MySQL Workbench (official tool)

       ![MySQL Workbench](res/20211106063939.png)

   - Navicat for MySQL (simple and friendly interface)

       ![Navicat](res/20210521152457.png)

## Basic MySQL Commands

### View Commands

1. View all databases

```sql
show databases;
```

2. View all character sets

```sql
show character set;
```

3. View all collation rules

```sql
show collation;
```

4. View all engines

```sql
show engines;
```

5. View all log files

```sql
show binary logs;
```

6. View all tables in a database

```sql
show tables;
```

### Getting Help

In the MySQL command-line tool, use the `help` command or `?` to get help:

1. View help for the `show` command.

    ```mysql
    ? show
    ```

2. View available help topics.

    ```mysql
    ? contents
    ```

3. Get function help.

    ```mysql
    ? functions
    ```

4. Get data type help.

    ```mysql
    ? data types
    ```

### Other Commands

1. Create/reset server connection - `connect` / `resetconnection`.

2. Clear current input - `\c`. Use this when you make an error to clear the current input and start over.

3. Change the terminator (delimiter) - `delimiter`. The default terminator is `;`, but you can change it using this command, for example, to `$`: `delimiter $`.

4. Open system default editor - `edit`. After editing and saving, the command line automatically executes the edited content.

5. View server status - `status`.

6. Change default prompt - `prompt`.

7. Execute system commands - `system`. Place system commands after the `system` command; it can also be abbreviated as `\!`.

8. Execute SQL file - `source`. Follow `source` with the SQL file path.

9. Redirect output - `tee` / `notee`. Redirect command output to a specified file.

10. Switch database - `use`.

11. Show warning messages - `warnings`.

12. Exit command line - `quit` or `exit`.
